# Translating RAPX

Languages live in `mods/rapx/mod.yaml` (`FluentLanguages`). Each one loads, on top of the English messages:

- `mods/rapx/fluent/lang/<lang>/game.ftl`: GENERATED by `tools/lang/l10n.py merge <lang>`, never edit by hand
- `mods/rapx/fluent/lang/<lang>/chrome.ftl`: hand-written core UI (menus, settings, lobby, nations); it wins over game.ftl

Anything untranslated shows in English.

## Workflow

1. `python3 tools/lang/l10n.py texts`: collect the English text written in C# (`PxText.T/F/N`) into `fluent/px-text.ftl`.
2. `python3 tools/lang/l10n.py export <lang>`: writes `tools/lang/work/<lang>/todo.txt`, one unique English text per line:
   `<id><TAB><text>`. Re-exporting renumbers the ids, so never re-export while a translation is in progress.
3. Translate into `tools/lang/work/<lang>/done-NN.txt` files (any number, any order), each line `<id><TAB><translation>`.
4. `python3 tools/lang/l10n.py merge <lang>`: builds game.ftl and rejects lines whose `{ ... }` placeables differ from
   the English line. `python3 tools/lang/l10n.py status` shows coverage.

## Rules for the translation lines

- One line per id, a single TAB after the id. No line breaks inside a line: `\n` (backslash + n) marks a line break,
  as in the English. Keep the line breaks in the same places, or re-wrap long text at similar line lengths.
- Copy every Fluent placeable exactly: `{ $player }`, `{ $p0 }`, `{ -term }`, `{"{"}` and so on. Never add a bare `{` or `}`.
- Select expressions (`{ $count ->\n[one] ...\n*[other] ...\n}`) keep the same structure and the same variant keys
  (`[one]`, `*[other]`); translate only the text inside the variants. For languages without plurals write the same
  text in both variants.
- A line must not start with `[`, `*` or `.` after a `\n` unless it is a variant key of a select expression.
- Keep proper names as they are: Project X, Red Alert, OpenRA, Godzilla, Kong, unit model codes (AB-35, F-16 ...),
  key names (Ctrl, Shift, Alt, <Left> ...), `$`, numbers and units.
- If the English is ALL CAPS, write the translation in capitals too (for scripts that have them).
- Space on screen is tight: short labels (buttons, column headers, chips, stat names) must stay about as short as
  the English. Descriptions can be natural length.
- Military/RTS register, the way a commercial strategy game in that language would say it. Be consistent:
  the same English term always gets the same translation.
- Use the established words from `mods/rapx/fluent/lang/<lang>/chrome.ftl` (side names Union/Vanguard, menu terms).

## Unit descriptions: "Strong vs" lines

The production tooltip turns lines like `Strong vs Infantry and Tanks` into icon rows. It recognises them in other
languages from the translations of these todo.txt entries, so translate those first and then reuse them exactly:

- the prefixes `Strong vs ` and `Weak vs ` (keep the trailing space; it is part of the text),
- the separators ` and `, `, and `, `, ` (keep their spaces),
- the target words listed in `PxTextExtra.Terms` (OpenRA.Mods.RAPX/PxTextExtra.cs): Aircraft, Vehicles, Infantry,
  Buildings, Anti-Air, Tanks, Ships, Submarines, Light armor, Missiles, Ground units, Fighters, Naval units, Drones,
  Robots, Light vehicles, Helicopters, Satellites, Rockets, Dogs.

Every translated `Strong vs` / `Weak vs` line must be exactly: translated prefix + terms joined with the translated
separators, using exactly the translated term words (other wording may follow after a `;` as in the English).
